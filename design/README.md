# デザイン指示書（Linear型）v1.0

作成日：2026-09-05 ／ 対象：BOSS案件で作るホームページ・LP・提案資料・管理画面のすべて

このフォルダにある3つのファイルが正本です。読み物ではなく、そのまま読み込んで使う実ファイルです。

| ファイル | 中身 | 使い方 |
| --- | --- | --- |
| `tokens.css` | 色・文字・余白・角丸・動きの決まった値 | 全ページで最初に読み込む |
| `components.css` | ボタン・カード・表・入力欄などの部品 | `tokens.css` の次に読み込む |
| `sample.html` | 部品を全部並べた見本ページ | スマホで開いて見た目を確認する |

---

## 0. なぜLinear型を採用したか

これまでは、ページを作るたびに色も余白も文字の大きさも決め直していました。結果、同じ案件の中でも見た目が揃わず、直すたびに全体が崩れていました。

Linear型を採用した理由は3つです。

1. **選択肢が少ない。** 色は面3段階・線3段階・文字4段階・アクセント1色だけ。迷う余地がないので、誰が作っても同じものが出ます。
2. **地味な作りなので、中身の粗が目立つ。** 派手な装飾で誤魔化せません。文章と構成が良ければそのまま良く見えます。
3. **AIに指示しやすい。** 「カードは `.card`、ボタンは `.btn--primary`」と部品名で伝えられるので、指示文が短くなり、出てくるものがぶれません。

---

## 1. 使い方（新しいページを作るとき）

`<head>` に2行足すだけです。

```html
<link rel="stylesheet" href="/design/tokens.css">
<link rel="stylesheet" href="/design/components.css">
```

そのあとは、`sample.html` に出ている部品を組み合わせて本文を書きます。

```html
<div class="container section stack">
  <h2>見出し</h2>
  <p>本文。</p>
  <div class="grid">
    <div class="card">
      <div class="card__title">項目名</div>
      <div class="card__body">説明文。</div>
    </div>
  </div>
  <div class="row">
    <button class="btn btn--primary">申し込む</button>
    <button class="btn btn--secondary">資料を見る</button>
  </div>
</div>
```

---

## 2. 守ること（この5つだけ）

1. **生の値を書かない。** `#5e6ad2` や `16px` を直接書かず、`var(--accent)` `var(--space-4)` を使う。値を変えたいときは `tokens.css` の1か所だけ直す。
2. **主のボタンは1画面に1つ。** 2つ置くと、どちらも主でなくなります。
3. **余白は4pxの倍数だけ。** 「なんとなく13px」を作らない。
4. **状態の色で面を塗らない。** 赤・緑・黄は文字と線にだけ乗せる。面を塗ると画面が騒がしくなります。
5. **触っても位置を動かさない。** カードを浮き上がらせる、拡大する、といった動きは付けない。変えるのは線の明るさと面の明るさだけ。

---

## 3. 決めた値（要点だけ。全部は `tokens.css` を見る）

| 項目 | 値 | 理由 |
| --- | --- | --- |
| 本文の文字 | **14px** | 16pxではありません。情報の密度が上がり、business向けの見え方になります |
| 見出しの字間 | -0.022em | 見出しだけ詰める。本文の日本語は詰めると読みにくくなるので詰めません |
| 行間（本文） | 1.7 | 和文は欧文より広く取ります |
| 角丸 | 6px（部品）／8px（カード） | 丸すぎると「かわいい」側に寄ります |
| 動きの速さ | 150ms前後 | 200msを超えると、もたつきます |
| 影 | ほぼ使わない | 浮かせるのは「1pxの線」と「上辺に乗せた白1px」で行います |

**上辺の白1px（`--ring-inset`）が、この型の質感のほぼ全部です。** カードやボタンの上の縁にだけ薄い白を乗せると、光が当たっているように見えます。ここを外すと、ただの黒い箱になります。

---

## 4. 和文フォントの注意

Linearは Inter という欧文フォントを使っていますが、Interに日本語は入っていません。指定を欧文だけで終えると、Windowsで MS Pゴシックが出て、まったく別物になります。

`tokens.css` の `--font-sans` は、欧文（Inter）→ macOS の和文（Hiragino Sans）→ Windows の和文（Yu Gothic UI / Meiryo）の順に必ず繋いであります。**ここを短縮しないでください。**

また `font-feature-settings: "palt" 1` を `body` に入れてあります。日本語の約物（「」、。）の余分な空きを詰める指定で、これが無いと和文だけ間延びして見えます。

---

## 5. スマホでの確認（必須）

成果物はスマホでしか見られない前提です。作ったら必ずスマホ幅で開いて、次の4つを見てください。

1. 横スクロールが出ていないか（表は `.table-wrap` で囲めば箱の中だけで流れます）
2. ボタンが指で押せる高さ（44px）になっているか
3. 見出しが2行以上に折り返して不格好になっていないか
4. 文字が小さすぎないか（本文14pxはスマホでも読めますが、注記の11pxを本文に使わないこと）

`components.css` の末尾に640px以下の指定をまとめてあります。スマホ側で直したいことがあれば、そこに足してください。

---

## 6. 明るい面（ライトテーマ）

営業資料を印刷する、白背景でスクリーンショットを貼る、といった場合に使います。`<html>` に属性を1つ足すだけで切り替わります。

```html
<html lang="ja" data-theme="light">
```

色の「役割」は変えず、値だけ入れ替えてあるので、ページ側のHTMLは1文字も変えずに済みます。

---

## 7. 次の一手

1. `sample.html` をスマホで開いて、見た目に異論がないかを確認する
2. 異論がなければ、既存のページ（`サイトページ`）をこの型に載せ替える
3. 以後、新規ページは必ずこの2ファイルを読み込んで作る

見た目を変えたくなった場合は、ページ側を直さず `tokens.css` の値を1か所変えてください。全ページに同時に反映されます。
